# Ruby on Rails Tutorial sample application

Лабораторная работа №7: регистрация пользователей.

Это учебное приложение для книги
[*Ruby on Rails Tutorial: Learn Web Development with Rails*](https://www.railstutorial.org/)
Майкла Хартла ([Michael Hartl](https://www.michaelhartl.com/)), глава 7.
Работа продолжает приложение из лабораторной №6.

## Зависимости

- Ruby 4.0.7
- Rails 8.1.3.1
- SQLite (база `storage/development.sqlite3`, в git не попадает)

## Как начать

```bash
bundle install
bin/rails db:migrate
bin/rails test
bin/rails server
```

## Что сделано

### Демонстрация пользователей (7.1)

- В шаблон сайта добавлена отладочная информация `debug(params)`, видимая
  только в окружении development (листинг 7.1), со стилями и примесью Sass
  `box_sizing` (листинг 7.2).
- `resources :users` в маршрутах даёт полный набор RESTful URL
  (листинг 7.3, таблица 7.1). GET `/users/1` ведёт к действию `show`
  с `User.find(params[:id])` (листинг 7.5) и представлению
  `users/show.html.erb` (листинг 7.4).
- Отладчик: в действие `show` добавлялась строка `debugger` для изучения
  состояния приложения и затем удалена (листинги 7.6 и 7.7).
- Страница профиля показывает граватар и боковую панель: хелпер
  `gravatar_for` строит URL по MD5-хешу email (листинги 7.8 и 7.9),
  представление обёрнуто в `aside` с классами Bootstrap (листинг 7.10),
  стили сайдбара в SCSS (листинг 7.11).

### Форма регистрации (7.2)

- Переменная `@user` в действии `new` (листинг 7.12) и форма через
  `form_for` с полями имени, email, пароля и подтверждения
  (листинг 7.13). Стили полей ввода (листинг 7.14).
- База development очищена задачей `db:migrate:reset` перед переходом
  к созданию пользователей через веб.

### Провальная регистрация (7.3)

- Действие `create` со строгими параметрами: приватный метод `user_params`
  разрешает только `name`, `email`, `password`, `password_confirmation`
  (листинги 7.16 и 7.17). При неудачном `save` заново отображается форма.
- Сообщения об ошибках: партиал `shared/_error_messages.html.erb` со
  счётчиком через `pluralize` (листинги 7.18 и 7.19), стили для
  `error_explanation` и `field_with_errors` (листинг 7.20).
- Интеграционный тест: невалидная отправка не меняет `User.count` и заново
  отображает `users/new` (листинг 7.21).

### Успешная регистрация (7.4)

- При успешном сохранении пользователь перенаправляется на страницу профиля
  (листинг 7.23) с флэш-сообщением `flash[:success]` (листинг 7.24),
  выводимым в шаблоне сайта (листинг 7.25, затем переписан через
  `content_tag` в упражнении, листинг 7.34).
- Первая регистрация выполнена через форму: пользователь "Rails Tutorial"
  с адресом example@railstutorial.org создан, флэш показан и исчез
  после перезагрузки страницы (7.4.3).
- Интеграционный тест: валидная отправка увеличивает `User.count` на
  единицу, после перенаправления отображается `users/show` (листинг 7.26).

### Развертывание (7.5)

- В production включён `config.force_ssl = true` (листинг 7.27).
- Веб-сервер — Puma (листинги 7.28 и 7.29), добавлен `Procfile`
  с `web: bundle exec puma -C config/puma.rb` (листинг 7.30).
- Heroku не используется, развертывание не выполнялось.

### Упражнения (7.7)

- `gravatar_for` принимает необязательный размер: `gravatar_for user, size: 50`
  (листинг 7.31).
- Тесты сообщений об ошибках: `assert_select` для `div#error_explanation` и
  `div.field_with_errors` (листинг 7.32).
- Тест флэша: `assert_not flash.empty?` после успешной регистрации
  (листинг 7.33).
- Флэш в шаблоне переписан через `content_tag` (листинг 7.34).

## Отличия от учебника

- **Версии.** Книга написана для Rails 5, здесь Rails 8.1.3.1 и Ruby 4.0.7.
  Поэтому в интеграционных тестах параметры передаются через
  `params: { user: {...} }`, а устаревший `post_via_redirect` заменён
  парой `post` + `follow_redirect!`.
- **Puma** уже входит в Gemfile для всех окружений (стандарт Rails 8),
  поэтому отдельная группа `:production` с гемами `pg` и `rails_12factor`
  не создавалась, а `config/puma.rb` оставлен в современном виде.
- **Граватар** подгружается с `https://secure.gravatar.com`, как в книге.
- Heroku, облачная IDE и GitHub не используются, ветки не создаются.
